ICMP まとめ

Internet Control Message Protocol：IP通信のエラー通知や疎通確認を担うプロトコル

概要 パケット構造 Type一覧 主なCode ping traceroute Path MTU Discovery エラー送信のルール ICMPv6 セキュリティ 覚えるポイント

概要

レイヤネットワーク層（L3）。IPと一緒に動く制御用プロトコル
カプセル化IPパケットのデータ部に入る（IPプロトコル番号 = 1）。TCP/UDPは使わない
ポート番号なし。代わりに Type と Code でメッセージの種類を区別する
規格RFC 792（ICMPv4）／ RFC 4443（ICMPv6）
主な役割① 疎通確認などの問い合わせ（ping）
② 配送できなかったときのエラー通知（到達不能・TTL切れなど）
ポイント ICMPはIPの「おまけ」ではなく、IPの実装に必須の一部です。IPは配送を保証しないので、問題があったことを送信元に伝える手段としてICMPを使います。

パケット構造

共通ヘッダ（先頭4バイト）

081631
Type8bit
Code8bit
Checksum16bit
Rest of Header32bit（Typeごとに中身が違う）
Data可変長

Echo（Type 0 / 8）の場合

  • Rest of Header ＝ Identifier（16bit）＋ Sequence Number（16bit）
  • Identifier：どのpingプロセスか
  • Sequence：何回目の要求か（応答と対応づける）
  • Data：任意。応答はこれをそのまま返す

エラーメッセージの場合

  • Data ＝ 原因になったパケットのIPヘッダ＋先頭8バイト
  • 先頭8バイトにはTCP/UDPのポート番号が入っているので、送信元はどの通信のエラーか判別できる
  • Type 3 Code 4 では Rest of Header に次ホップのMTUが入る

主な Code

Type 3：宛先到達不能

Code意味誰が返すか・どんなとき
0ネットワーク到達不能（Net Unreachable）ルータ：宛先ネットワークへの経路がない
1ホスト到達不能（Host Unreachable）ルータ：宛先ホストが応答しない（ARP解決できないなど）
2プロトコル到達不能（Protocol Unreachable）宛先ホスト：指定されたプロトコルに対応していない

※TCPの場合はICMPではなくRSTで拒否する
4フラグメント必要（Fragmentation Needed and DF set）ルータ：パケットがMTUより大きいがDFフラグで分割禁止。Path MTU Discoveryで使う
5ソースルート失敗ソースルーティングで指定された経路を通れない
9 / 10ネットワーク／ホストへの通信が管理上禁止ルータの設定で禁止されている（古い定義）

ping の動き

送信元
Type 8 エコー要求（seq=1）
宛先
Type 0 エコー応答（seq=1）
  • Identifier と Sequence Number で要求と応答を対応づけ、往復時間（RTT）を計測する
  • 応答がない＝ダウン、とは限らない。ファイアウォールがICMPを遮断していることも多い
  • 途中で届かなかった場合は、ルータから Type 3（到達不能）や Type 11（TTL切れ）が返ってくることもある

経路上で通せる最大のパケットサイズ（Path MTU）を調べる仕組みです。

PMTUブラックホール ICMPを全部遮断すると Type 3 Code 4 も届かなくなり、大きなパケットだけが黙って捨てられます。「pingは通るのにWebページが途中で止まる」といった症状の原因になります。

エラーメッセージを送らないケース

エラーの連鎖やトラフィックの爆発を防ぐため、次のパケットに対してはICMPエラーを返しません。

  • ICMPエラーメッセージそのもの（エラーのエラーは返さない。Echoなど問い合わせ型には返す）
  • ブロードキャスト・マルチキャスト宛てのパケット
  • 2番目以降のフラグメント（先頭フラグメントのみ対象）
  • 送信元アドレスが特定のホストを表さないもの（0.0.0.0、ループバックなど）

また、多くの機器は ICMP の送信数に上限（レート制限）を設けています。

ICMPv6 との違い

IPv6ではICMPの役割が大きくなり、ARPやIGMPの機能も取り込んでいます。Next Header = 58。

1宛先到達不能Type 3
2パケット過大（Packet Too Big）Type 3 Code 4 に相当。IPv6ではルータが分割しないので必須
3時間超過（Hop Limit 超過）Type 11
4パラメータ異常Type 12
128エコー要求Type 8
129エコー応答Type 0
133 / 134ルータ要請 / ルータ広告（RS / RA）Type 10 / 9。SLAACでのアドレス自動設定に使う

番号の付け方 ICMPv6では、Type 0〜127 がエラーメッセージ、128〜255 が情報メッセージです。133〜137 をまとめて NDP（近隣探索プロトコル）と呼びます。IPv6でICMPv6を全部遮断すると、通信そのものができなくなります。

セキュリティ上の注意

Ping Flood

大量のEcho Requestを送りつけて帯域や処理能力を使い切らせるDoS攻撃。

Smurf 攻撃

送信元を被害者のIPに偽装し、ブロードキャストアドレス宛てにEcho Requestを送る。大量のEcho Replyが被害者に集中する。

Ping of Death

65,535バイトを超える不正なパケットをフラグメントで送り、再構築時にシステムを停止させる（古いOSの脆弱性）。

ICMP トンネリング

Echoのデータ部に別の通信を埋め込み、ファイアウォールを通り抜ける。情報持ち出しなどに使われる。

Redirect の悪用

偽のリダイレクトで通信経路を書き換え、中間者攻撃につなげる。多くのOSは受信を無効にしている。

偵察（スキャン）

Echoで生きているホストを探したり、Type 3 Code 3の有無でUDPポートの開閉を調べたりする。

対策の考え方 ICMPを全部止めるのではなく、必要なもの（Type 3 Code 4 / ICMPv6 Type 2、NDPなど）は通し、不要なもの（Redirect、Timestamp、外部からのEcho Requestなど）を選んで遮断・レート制限するのが基本です。
